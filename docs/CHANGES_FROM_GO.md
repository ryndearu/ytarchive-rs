# Changes from the Go source

This port is based on [dreammu/ytarchive](https://github.com/dreammu/ytarchive) at commit `010de44` (2026-10-10), a fork of [Kethsar/ytarchive](https://github.com/Kethsar/ytarchive) at `2110ce2` (2025-06-25). Everything that behaves differently is listed here; anything else is meant to behave the same.

## New features

- **`--sqlite`** (idea from [CanOfSocks/livestream_dl](https://github.com/CanOfSocks/livestream_dl)): fragments are stored in `{name}.f{itag}.sqlite` in the temp directory as they arrive and exported in order to the `.ts` file at the end. Resuming fetches only the missing ones. A download is resumed in the storage it was started with, whatever the flags say.
- **`--recover-private`** (idea from livestream_dl; turns on `--sqlite`): once a stream went private, Go stopped at the first 403 (the port still does without the flag). With it, every missing fragment is retried with all the URLs used so far, in rounds 5 minutes apart, until all are recovered, the URLs expire, or 12 rounds in a row recover nothing. If fragments are still missing and a URL hasn't expired, the temp directory, database, and state files are kept, and the same command retries only those fragments, also after a killed run (see [Private streams and missing fragments](../README.md#private-streams-and-missing-fragments)).
- **`--codec LIST`**: the video codec order, e.g. `--codec vp9/h264`. Go's `--av1`/`--vp9`/`--h264` still work but can't be combined with it.
- **The channel monitor skips streams it already recorded.** `/live` can keep pointing to an ended stream, and Go could download it again.
- **An ended stream whose live download is gone is reported**: "Livestream has already ended; its live download no longer exists. Use yt-dlp instead." This is decided from yt-dlp's live URLs. Go looked only at the watch page's first format, printed "has been processed" or "is being processed", and could show the members-only hints instead.

## Changed behavior

### Command line

- The help text is generated by clap, grouped under headings. All Go flag names still work, including single-dash long flags (`-threads`, `-td`, `-dp`, `-fp`), except `--potoken` and `--visitor-data`: dreammu accepted but never used them, so they are removed. Pass PO token settings with `--ytdlp-opts`.
- `--file-permissions` / `--directory-permissions` are always octal (`755` means `0755`). Go read `755` as decimal.
- These are errors: `--metadata` without `=` (Go crashed), `--no-video` with `--no-audio`, and `--threads 0`.
- The scheduled-stream question is numbered: `1) wait  2) poll  3) no (default 3):` (`wait`/`poll` still work; Enter and closed stdin mean no). Go asked `wait/poll/[no]:`.
- `--ytdlp-info` asks for the quality while waiting for a scheduled stream. Go asked once the stream started.
- When none of the chosen qualities are available, `best` is used. Go asked again, which stalled an unattended download.
- The version includes the build date, and the commit for non-release builds: `v0.1.0 (2026-11-07)`, `v0.1.0-abc1234 (2026-11-07)`.
- Arguments that aren't valid UTF-8 are converted instead of rejected.
- yt-dlp gets a repaired copy of a cookies file it can't read (the cases are under [PO tokens and cookies](../README.md#po-tokens-and-cookies)). Go passed the file as it was, and yt-dlp failed.

### Downloading

- The URL is passed to yt-dlp after `--`, so it can't be read as an option.
- A yt-dlp run may take 60 seconds (Go: 30) before it is stopped and tried again.
- yt-dlp runs with `--encoding utf-8` (and `PYTHONIOENCODING=utf-8`, `PYTHONUTF8=1`), so text arrives as UTF-8 whatever the console's code page is. `--ytdlp-opts` can override it.
- **A download from a channel URL stays on the stream it started on** in `--ytdlp-info` mode too: URL refreshes use the stream's watch URL. Go kept refreshing through `/live` and could switch streams mid-download.
- **Waiting on a channel keeps checking `/live`** (`--monitor-channel`, or a channel URL with `-r`). When `/live` showed a playable stream that hadn't started, Go switched to its watch URL and missed another stream that started first.
- Non-2xx responses are errors (Go's page and thumbnail fetches accepted any). Error and `--debug` messages omit URL query strings, which hold signatures and your IP.
- A connection that sends nothing for 30 seconds is dropped. Go had no limit.
- **Retries slow down when the server is the problem.** After a connection error, a 5xx, or a 429, the wait doubles for each such failure in a row (up to 15 seconds, or the fragment duration if longer), and `Retry-After` is followed up to 60 seconds. Go always waited one fragment duration; the port still does for 404s, empty responses, and 403s.
- **A live fragment that never downloads is skipped.** Go retried it for as long as the stream was live, holding back everything after it. The port gives up once its tries (`--retry-frags`) have run out 4 times while at least 30 other fragments downloaded. During an outage, and with `--retry-frags 0`, fragments are retried without limit.
- **With `--no-frag-files`, the memory behind a missing fragment is limited.** Once 256 MiB of a stream wait behind it, no new fragments start until it arrives or is given up on (after its tries have run out 4 times; never with `--retry-frags 0`). Go had no limit.
- **Failing fragments don't keep a `--capture-duration` download from finishing.** After the capture's last fragment has started, each failing one is given up on once its tries have run out 4 times, if anything else downloaded since it was first tried. An outage during the last fragments that lasts that long loses them.
- **A failed scheduled URL refresh is tried again after 5 minutes.** Go waited another 5 hours, longer than the URLs last (about 6 hours).
- SQLite inserts and the export, saving the resume state, and moving finished files to another filesystem no longer hold up the download. The state file can be a few fragments behind the data; resuming cuts the data file back to it.
- A temp directory named in a state file is reused only if it still exists.
- `--separate-audio` makes the extra file only when both audio and video were downloaded. Go also duplicated audio-only downloads.

### Files and cleanup

- Only temp directories named `{video_id}__*` are ever deleted. Go deleted whatever directory a state file named.
- The final file's name (`name.mp4`, `name-1.mp4`, …) is picked right before muxing, and the `.ffmpeg.txt` command is updated to match. Go picked it before the download, so a file that appeared meanwhile made ffmpeg fail.
- When `name.mp4` to `name-10.mp4` all exist, ffmpeg isn't run and the `.ts` files are kept. Go ran ffmpeg and reported only its exit code.
- `publish_date` is always `YYYYMMDD`. Go kept the raw value, which can include a time and offset.

### Output and signals

- The progress line is written to stderr (Go: stdout).
- A second Ctrl-C exits immediately, like Go's `signal.Reset`.

## Platform support

Windows, Linux, and macOS are supported, each as x64 and arm64. Go built for more targets but supported only Linux and Windows, and had no Windows arm64 build.

- **TLS is rustls** (with `ring`) and the operating system's certificate store. No OpenSSL is needed, so the Linux builds are static.
- **Windows console** (port of `util_windows.go`): the system is kept awake, ANSI colors are enabled, and QuickEdit mode is turned off and restored on exit, all through safe wrapper crates (no `unsafe`).
- **`--windows-filenames` / `--no-windows-filenames` / `--no-path-limit`** (new). With Windows names (default on Windows), forbidden and control characters, reserved names, and trailing dots and spaces are replaced in the file name and every folder from the template, and the title is shortened so every path fits in MAX_PATH (`--no-path-limit` turns that off). Without them, only path separators and NUL are replaced. Go always replaced `<>:"/\|?*`, only in the file name.
- **The `.ffmpeg.txt` command uses the platform's quoting.** Go always used POSIX quoting.
- **`ffmpeg`/`yt-dlp` next to the executable are found**, besides `PATH`. Go also looked in the current directory.

## Go bugs fixed during the port

1. **The filename blacklist was never applied**, so `%(description)s` inserted the whole description.
2. **Template expansion could loop forever** when a value contained its own placeholder. Substitution is now single-pass.
3. **Long names weren't shortened enough** when a template used `%(title)s` more than once.
4. **Session cookies (expiry `0`) were dropped.**
5. **The `--live-from` 7-day check compared a fragment count with seconds.**
6. **An empty start timestamp or a malformed googlevideo `id` crashed.**
7. **"Try N more times" never retried**: the try counter wasn't reset.
8. **One bad fragment ended the download** of an ended stream, dropping everything after it. The port skips it and lists the missing sequence numbers.
9. **Slower workers gave up early** when another worker reached the last sequence.
10. **Resuming with a missing data file** wrote into a new empty file. It now starts over.
11. **MP4 box scanning** hung on a zero-length box and looked only at the first 8 KiB of a fragment.
12. **The ffmpeg command could name a thumbnail that failed to download.**
13. **The audio/video mismatch warning never fired.**
14. **Disabling QuickEdit never worked**: the `ENABLE_EXTENDED_FLAGS` bit was missing.
15. **Page downloads failed with HTTP/2 errors** (port-specific): YouTube's ~20 KB of response headers exceeded the HTTP library's 16 KB default.
16. **`--file-permissions` skipped the muxed file** and the `--separate-audio` file.
17. **Repeating a flag was an error** (port-specific, v0.1.0). The last value wins, as in Go; `--metadata` collects every value.
18. **Ctrl-Break didn't stop the download on Windows** (port-specific, v0.1.0). It now acts like Ctrl-C, as in Go.
19. **A download that couldn't be stored was still "finished" and muxed.** When a data file or database couldn't be opened, Go ran ffmpeg on the missing file (code -22). The port doesn't merge and exits with 1: with nothing downloaded it removes the temp folder and state files, otherwise it leaves everything to resume. The same applies when storing fails later, e.g. a full disk or a failed `--sqlite` export (port-specific: v1.0.0 merged and removed the state files).
20. **A crash while saving the state could lose the download.** Go rewrote the `.state` file in place, and after an unreadable state the next run overwrote the data. The port writes a temporary file and renames it, and keeps data it can't resume as `{name}.f{itag}.ts.old` (its temp folder is then not cleaned up). The state file isn't synced to disk (that made each save about 20 times slower), so a power loss isn't covered.

## Not ported

Unreachable, unused, or only documented in Go:

- **InnerTube player request** (`DownloadWebAPIPlayerResponse`), the `ytcfg` scraping that fed it, and **SAPISIDHASH** authentication.
- **DASH manifest parsing** (`GetUrlsFromManifest`, `MPD` types): yt-dlp provides the URLs.
- **UMP parsing** (`yt_ump.go`).
- **Slow-fragment URL refresh**: Go counted slow fragments, but the refresh call is commented out.
- **`--info-only`**: in dreammu's README, but neither Go codebase implements it.
