# Changes from the Go source

Based on [dreammu/ytarchive](https://github.com/dreammu/ytarchive) at `010de44` (2026-10-10), a fork of [Kethsar/ytarchive](https://github.com/Kethsar/ytarchive) at `2110ce2` (2025-06-25). Anything that behaves differently is listed here; the rest should match.

## New features

- **`--sqlite`** (idea from [CanOfSocks/livestream_dl](https://github.com/CanOfSocks/livestream_dl)): fragments go to `{name}.f{itag}.sqlite` in the temp directory as they arrive, then export in order to the `.ts` file. Resuming fetches only the missing ones. A download resumes in the storage it started with, whatever the flags say, and honors `--no-audio`/`--no-video`.
- **`--recover-private`** (from livestream_dl; implies `--sqlite`): Go stopped at the first 403 once a stream went private. With it, missing fragments are retried with the URLs already used, and a later run can retry what's still missing. See [Private streams](../README.md#private-streams-and-missing-fragments).
- **`--codec LIST`**: video codec order, e.g. `--codec vp9/h264`. Go's `--av1`/`--vp9`/`--h264` still work but can't be combined with it. A codec before `best` keeps its place (`vp9/best` tries VP9 first). Unknown names are errors, even next to `best`.
- **The channel monitor skips recorded streams.** Go could re-download an ended stream that `/live` still pointed to. Recorded IDs are skipped when scanning `/streams` (so simultaneous streams are picked up) and before running `yt-dlp`. A stream whose download or `--live-from` resolution fails is retried once, then marked done after 2 failures. An early exit waits only the rest of the poll interval (Go slept all of it).
- **Ended-stream message:** "Livestream has already ended; its live download no longer exists. Use yt-dlp instead." It's decided from yt-dlp's live URLs. Go checked only the watch page's first format and could show members-only hints instead. yt-dlp errors and Ctrl-C don't print it.

## Changed behavior

### Command line

- Help is generated by clap and grouped. All Go flags work, including single-dash long flags (`-threads`, `-td`, `-dp`, `-fp`), except `--potoken` and `--visitor-data`: dreammu accepted them but never used them. Use `--ytdlp-opts` for PO tokens.
- `--file-permissions` and `--directory-permissions` are always octal (`755` is `0755`). Go read `755` as decimal.
- New errors: `--metadata` without `=` (Go crashed), `--no-video` with `--no-audio`, `--threads 0`, and unclosed quotes in `--ytdlp-opts`.
- `--ytdlp-opts` handles single and double quotes (Windows backslashes are kept outside quote escapes). `--live-from` syntax and the 7-day bound are checked at startup. `--metadata` templates with unknown keys warn at startup and keep the literal fallback.
- Huge `--live-from`, `--start-delay`, and `--capture-duration` values saturate instead of overflowing. Go's integer math could wrap.
- Scheduled-stream prompt: `1) wait  2) poll  3) no (default 3):`. `wait` and `poll` still work, and Enter or closed stdin means no. Go asked `wait/poll/[no]:`.
- `--ytdlp-info` asks for the quality while waiting. Go asked once the stream started.
- If none of the chosen qualities exist, `best` is used. Go asked again, which stalled unattended runs. With `--no-audio`, `audio_only` is never selected or offered.
- The version shows the build date, and the commit for non-release builds: `v0.1.0 (2026-11-07)`, `v0.1.0+abc1234 (2026-11-07)`.
- Non-UTF-8 arguments are converted instead of rejected.
- `-4`/`-6` are forwarded to yt-dlp (`--force-ipv4`/`--force-ipv6`), so extracted URLs match the download's IP family. Go bound only its own HTTP client.
- `--proxy` accepts `socks5h://` (remote DNS). Go rejected it.
- `--members-only` warns and is ignored on video URLs (Go skipped the watch page and failed). It warns on channel URLs without `--cookies`.
- A cookies file yt-dlp can't read (not UTF-8, no Netscape header, a domain column that doesn't match its leading `.`, or a stray JSON-like line) is passed to yt-dlp as a repaired copy in the temp folder, deleted on exit. Go passed the file unchanged and yt-dlp failed.
- `/live/`, `/shorts/`, and `youtu.be/` URLs: the video ID is the first path segment. Go took the whole rest of the path.

### Downloading

- The URL goes to yt-dlp after `--`, so it can't be read as an option.
- A yt-dlp run may take 60 seconds (Go: 30) before it's stopped and retried.
- yt-dlp runs with `--encoding utf-8` (plus `PYTHONIOENCODING=utf-8` and `PYTHONUTF8=1`). `--ytdlp-opts` can override it.
- `--ytdlp-info`: an exact `format_id` (`140`) wins over a suffixed one (`140-drc`). Without an exact ID, the last suffixed variant is used. `target_duration` prefers adaptive formats.
- A `target_duration` under 0.5 seconds is 1 second. Go rounded it to 0 and kept its 5-second default.
- The `X-Head-Seqnum` HEAD probe sends the fragment's `Referer` and retries up to 3 times, 1 second apart, on missing headers or request errors. Go sent one request with no `Referer`.
- `--ytdlp-info` with `-r` on a channel URL polls once per interval, with no multi-attempt retries. It stops if yt-dlp can't start, and warns once per unexpected error. Negative `--live-from` on upcoming streams is rejected, and an `is_upcoming` report mid-download exits cleanly. Go failed at once on channels with no active stream.
- **Wall-clock waits:** scheduled waits, `-r` polling, `--monitor-channel` intervals, `--start-delay`, `--recover-private` rounds, and the 5-hour URL refresh track the wall clock, rechecked every 60 seconds, so system sleep doesn't stretch them. Go slept in one monotonic call.
- **A channel download stays on its stream.** In `--ytdlp-info` mode, URL refreshes use the stream's watch URL. Go kept refreshing through `/live` and could switch streams.
- **Retry counters reset after each valid poll** (watch page and `--ytdlp-info`), so scattered errors over a long wait don't abort it. Go never reset `responseRetryCount` or `videoDetailsRetryCount`.
- **Channel waits keep checking `/live`** (`--monitor-channel`, or a channel URL with `-r`). That includes empty `videoDetails` on an idle channel, and a resolved watch page that errors, shows `ERROR` or `UNPLAYABLE`, isn't a livestream, is private or offline, or hasn't started. Go switched to the not-yet-started watch URL and missed a stream that started first. Channel URLs (including `m.youtube.com`) normalize to `https://www.youtube.com/.../live`. Empty handles and IDs are rejected.
- **The channel wait prints each new stream's channel and title** when another stream starts first, and doesn't repeat them once downloading. Go printed them once.
- Non-2xx responses are errors (Go accepted any status for page and thumbnail fetches). Error, `--debug`, and `--trace` output omit URL query strings (signatures, your IP), proxy credentials, and yt-dlp secrets: passwords and PO tokens.
- A connection that sends nothing for 30 seconds is dropped (Go had no limit).
- **Backoff on server trouble:** after a connection error, a 5xx, or a 429, the wait doubles per consecutive failure, up to 15 seconds or the fragment duration if longer. `Retry-After` is followed up to 60 seconds. Go always waited one fragment duration. 404s, empty responses, and 403s still wait one duration.
- **Fragments that never download are skipped.** Go retried a live fragment for as long as the stream was live, holding back everything after it. The port gives up once its tries (`--retry-frags`) have run out 4 times while at least 30 other fragments downloaded. During an outage, and with `--retry-frags 0`, retries are unlimited.
- **`--no-frag-files` limits memory:** once 256 MiB of data waits behind a missing fragment, no new fragments start until it arrives or is given up (same rule as above; never with `--retry-frags 0`). Go had no limit.
- `--threads 1` skips temporary fragment files, since fragments arrive in order.
- **`--capture-duration` finishes despite failing fragments.** After the capture's last fragment starts, each failing one is given up once its tries have run out 4 times, if anything else downloaded since. An outage that long loses them. On `.ts` resume the duration counts from `start_frag`, as with `--sqlite`.
- **A failed scheduled URL refresh is retried after 5 minutes.** Go waited 5 hours, longer than URLs last (about 6). Background and retry-triggered refreshes skip the `X-Head-Seqnum` probe and accept fragmented URLs without `last_sq`. Initial probes fall back across adaptive URLs. Scheduled refreshes skip finished streams, apply partial updates when only one stream misses, and stop once an ended stream reports no live URLs.
- **A URL refreshed after a 403 on an ended stream is tried.** Up to 2 refreshes per fragment reset the retry budget. Go's stale `is_403` flag stopped it. `is_403` clears on non-403 failures.
- **`--retry-frags 0` still refreshes URLs** every 10 failed attempts on a fragment. It keeps retrying while the stream is live, and stops on expired 403s or near-head end-of-stream failures once the stream has ended or gone unavailable, so downloads finish and `--recover-private` can run. Go disabled retry-triggered refreshes at 0.
- **Transient network errors during a refresh** don't mark a live stream unavailable permanently. Go did.
- **The refresh cooldown starts when extraction finishes** (and extraction is skipped once a stream is unavailable), so queued workers don't rerun slow extractions back to back. Go set it before extraction.
- **Mid-download `ERROR`, `UNPLAYABLE`, or unknown statuses** (such as `LOGIN_REQUIRED`) mark the stream both not live and unavailable. Go left `Unavailable` unset on `ERROR` and unknown, and `Live` set on `UNPLAYABLE`.
- **Storage work runs off the async runtime:** SQLite inserts (with batched head and URL updates), queries, exports, state saves, and moves to another filesystem. The state file can be a few fragments behind the data; resuming cuts the data back to it. SQLite exports wait until every stream finishes without storage errors (and past Ctrl-C prompts), so a failed stream never writes a `.ts` first. An unresumable database with zero fragments in its state is set aside as `.sqlite.old`, with its `-wal` and `-shm` files, which can hold fragments not yet checkpointed.
- A temp directory named in a state file is reused only if it still exists. Resuming inside an owned temp directory adopts an existing `.f{itag}.sqlite` (with WAL/SHM) or `.f{itag}.ts`, even if the stream title or `-o` changed.
- Finding a kept `--recover-private` database skips folders named like one (`*.f{itag}.sqlite`).
- **`--separate-audio`** writes the extra file only when both audio and video downloaded (Go also duplicated audio-only downloads). `.ffmpeg.txt` holds both commands, for `--write-mux-file`, `--save` on cancel, name changes, and mux failures. Go wrote only the main command.
- **A failed write to a temporary fragment file is a storage error:** the download stops, keeps its state, and isn't merged. Go counted it as a failed try, dropped the fragment once its tries ran out, and merged the rest.
- **A panic in a stream's download task or a fragment worker keeps the data.** Nothing is merged, and state files stay for resuming. With several threads at the live edge, the other workers wait for the lost fragment, so the download stops only when interrupted. Go has no `recover`, so a panic ended the program.

### Files and cleanup

- Only `{video_id}__*` temp directories are deleted. Go deleted whatever directory a state file named.
- Metadata values equal to `..` become `__`. Title truncation measures the name after lookalike characters are substituted and reserves room for the `-` and `_` prefixes and for the `.f{itag}.frag{seq}.ts` and `.f{itag}.sqlite-wal` suffixes, all within 255 bytes.
- Repaired cookies files get random names (`0600` on Unix) and are removed by an exit guard. Copies older than a day are cleaned up, except ones locked by a running `ytarchive`.
- The final name (`name.mp4`, `name-1.mp4`, …) is chosen just before muxing, and `.ffmpeg.txt` is updated to match. Go chose it before the download, so a file that appeared meanwhile broke ffmpeg.
- If `name.mp4` through `name-10.mp4` all exist, ffmpeg isn't run and the `.ts` files are kept. Go ran ffmpeg and reported only its exit code.
- State files are deleted only after moving the downloaded files succeeds. Partial copies and earlier exports from a failed batch are deleted, and ffmpeg doesn't run when a move fails.
- `--save` on cancel also moves `.ffmpeg.txt` to the output folder. Go deleted it with the temp folder.
- Failures applying `--file-permissions` or `--directory-permissions` (exFAT, FAT32, SMB) are logged at debug level, and written files are kept. Go's `os.WriteFile` never failed on a separate chmod, so the port matches that for filesystems that reject permissions.
- **On Windows, a rename that fails while antivirus or an indexer holds the file is retried** (up to 3 times, with short waits) before a state save or move fails. Go's `os.Rename` failed at once.
- `publish_date` is always `YYYYMMDD`. Go kept the raw value, which can include a time and offset.
- The `.ffmpeg.txt` command uses the platform's quoting. Go always used POSIX quoting. Newlines in metadata values become spaces, so each command stays on one line. Go wrote them as they were, splitting the command across lines.

### Output and signals

- The progress line goes to stderr (Go: stdout).
- Without a TTY, there are no ANSI escapes or `\r` rewrites. Under `--quiet`, `--newline`, or non-TTY stderr, there are no trailing inline newlines. `NO_COLOR` is respected.
- ffmpeg inherits stdout and stderr (silenced under `--quiet`) instead of being read through lossy UTF-8 chunks.
- A second Ctrl-C exits at once, like Go's `signal.Reset`.
- On Linux and macOS, `SIGTERM` stops the download without prompts, keeps the temp folder and state files, and exits 143. A second signal exits at once. Signals during ffmpeg muxing cancel it, remove partial output, keep the `.ts` files, and exit 143 (`SIGTERM`) or 2 (Ctrl-C). Prompts share the main signal listener.
- A download with 0 fragments exits 1 without running ffmpeg, and removes its empty temp folder unless `--recover-private` kept it.
- Ctrl-C at a prompt with closed stdin keeps temp files and state for resuming. Go treated EOF as "no" to every prompt and deleted the download.
- Interrupts cancel in-flight HTTP requests and kill running `yt-dlp` processes at once, instead of waiting for timeouts.

## Platform support

Windows, Linux, and macOS, each as x64 and arm64. Go supported Linux and Windows only, with no Windows arm64.

- **TLS** is rustls (with `ring`) and the OS certificate store. No OpenSSL, so Linux builds are static.
- **Windows console** (port of `util_windows.go`): keeps the system awake, enables ANSI colors, and turns off QuickEdit (restored on exit), through safe wrapper crates (no `unsafe`).
- **`--windows-filenames`, `--no-windows-filenames`, `--no-path-limit`**: new (see [File names](../README.md#file-names)). Go always replaced `<>:"/\|?*`, only in the file name, and didn't keep paths within MAX_PATH.
- **`.ffmpeg.txt` quoting** follows the platform. Go always used POSIX quoting.
- **`ffmpeg` and `yt-dlp` next to the executable** are found besides `PATH`, on every OS. Go also looked in the current directory.

## Go bugs fixed

1. **The filename blacklist was never applied.** `FormatFilename` blanked `description`, then overwrote it, so `%(description)s` inserted the whole description.
2. **Template expansion could loop forever.** `FormatPythonMapString` re-scanned substituted values, so a title containing its own placeholder never finished. Substitution is single-pass now.
3. **Long-name truncation was too small for repeated titles.** With `%(title)s` used more than once, only one copy was shortened. Every copy is shortened now.
4. **Session cookies were discarded.** Expiry `0` became 1970, which Go's cookie jar dropped.
5. **The `--live-from` 7-day check compared different units**: a fragment count against seconds.
6. **Missing timestamps crashed.** Slicing an empty timestamp panicked, and so did malformed googlevideo `id` parameters.
7. **"Try N more times" never retried.** `ContinueFragmentDownload` didn't reset the try counter, so the fragment was dropped.
8. **One bad fragment ended the download.** On an ended stream, a fragment well behind the head that failed permanently ended it, silently dropping everything after. The port skips it and lists the missing sequence numbers at the end. `Skipped` in the state (omitted when zero) stops resume from re-fetching and duplicating data.
9. **Slower workers gave up early.** A worker that reached the last sequence or hit a near-head failure marked the stream finished, abandoning other workers' retries. Such failures now only cap later sequences.
10. **A missing data file produced a broken file.** Go marked the download resumed and wrote into a new empty file. It starts over now. The progress line counts what storage holds, not the state file (v1.0.0 counted the state, pushing past "Max Fragments").
11. **MP4 box scanning hung and was incomplete.** A zero-length box made `GetAtoms` loop forever, and only the first 8 KiB of each fragment was scanned for `sidx`/`ftyp`.
12. **ffmpeg could reference a missing thumbnail.** Arguments were built before the thumbnail download. They are built after it now.
13. **The audio/video mismatch warning never fired.** The fragment counts it compared were never incremented.
14. **QuickEdit never stayed off.** Go cleared `ENABLE_QUICK_EDIT_MODE` without `ENABLE_EXTENDED_FLAGS`, which Windows requires. The port sets both and restores the original console mode on exit.
15. **`--file-permissions` skipped the final file.** Go applied it only to files it wrote itself. The muxed file and the `--separate-audio` file kept ffmpeg's default mode. The port sets it after muxing.
16. **An uncreatable file was still "finished" and muxed.** Go logged the error, printed "Download Finished", and ran ffmpeg on the missing file. The port doesn't merge and exits 1. A fresh temp folder and state files are removed, and a resumed download is left to resume once the cause is fixed.
17. **A crash while saving state could lose the download.** Go rewrote `.state` in place, so a crash mid-write left it unreadable, and the next run overwrote the data. The port writes a temp file and renames it. Unresumable data is kept as `{name}.f{itag}.ts.old` (or `.sqlite.old`), and opening storage aborts if that rename fails. The state isn't synced before the rename (syncing made each save about 20 times slower), so this covers program crashes, not power loss.
18. **A near-head transport error skipped the final fragments.** On an ended stream, Go treated the first transport error within two fragments of the head as end-of-stream, without retrying. The port retries transient errors normally. Immediate end-of-stream is for HTTP 404 and exhausted retries.
19. **Watch-page JSON extraction failed when more code followed the player response.** Go cut from the first `{` after the `ytInitialPlayerResponse` declaration to the last `};` in the script, so a later `};` left invalid JSON. The port reads one JSON object and stops.
20. **An ended stream could keep a download waiting.** Go updated `Live` only after yt-dlp returned URLs and a format was selected, so when a stream ended and its URLs were gone, workers still treated it as live and kept waiting on the head. The port updates it as soon as the stream's status is read.

## Not ported

Unreachable, unused, or documented only:

- **InnerTube player request** (`DownloadWebAPIPlayerResponse`), `ytcfg` scraping, and **SAPISIDHASH**. None are called in dreammu.
- **DASH manifest parsing** (`GetUrlsFromManifest`, `MPD`). yt-dlp provides the URLs.
- **UMP parsing** (`yt_ump.go`). Never called.
- **Slow-fragment URL refresh.** Go counted slow fragments, but the refresh call is commented out.
- **`--info-only`.** Listed in dreammu's README; neither Go codebase implements it.
