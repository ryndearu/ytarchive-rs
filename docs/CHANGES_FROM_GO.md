# Changes from the Go source

This port is based on [dreammu/ytarchive](https://github.com/dreammu/ytarchive)
at commit `010de44` (2026-10-10), a fork of
[Kethsar/ytarchive](https://github.com/Kethsar/ytarchive) at `2110ce2`
(2025-06-25). This file lists everything that behaves differently from that
source. Anything not listed here is meant to behave the same.

## New features

- **`--sqlite` storage** (idea from
  [CanOfSocks/livestream_dl](https://github.com/CanOfSocks/livestream_dl)).
  Fragments are stored in `{name}.f{itag}.sqlite` in the temp directory as
  soon as they arrive, then exported in order to the `.ts` file at the end.
  Resuming skips fragments already stored, so a later run only fetches the
  gaps.
- **`--info-only` works.** dreammu's README documents it, but neither Go
  codebase implements it. It prints the video ID, title, channel, selected
  quality, live status, and duration so far, then exits.
- **The channel monitor remembers recorded streams.** After a stream ends,
  a channel's `/live` page can keep pointing to it for a while, and Go could
  download the same stream again. The monitor now skips video IDs it has
  already recorded in the session.
- **Missing fragments are skipped and reported.** When a fragment well behind
  the head of an ended stream can't be downloaded, Go stopped the whole
  download there. The port skips that one fragment, keeps going, and lists the
  missing sequence numbers at the end.

## Changed behavior

### Command line

- The help text is generated by clap rather than Go's hand-written page. All
  Go flag names still work, including single-dash long flags (`-threads`,
  `-td`, `-dp`, `-fp`).
- `--file-permissions` / `--directory-permissions` (`-fp` / `-dp`) are always
  read as octal: `755` means `0755`. Go read `755` without a leading zero as
  decimal.
- `--metadata` without `=` is an error. Go crashed (index out of range).
- `--no-video` together with `--no-audio`, and `--threads 0`, are errors.
- `--potoken` and `--visitor-data` are accepted but ignored, with a warning.
  In dreammu they were also never used: the InnerTube request that consumed
  them (`DownloadWebAPIPlayerResponse`) is never called. Pass PO token
  settings to yt-dlp with `--ytdlp-opts` instead.
- `--ytdlp-info` asks for the quality while waiting for a scheduled stream, as
  the default mode does. Go asked only once the stream started.

### Downloading

- The URL is passed to yt-dlp after `--`, so a URL can never be read as a
  yt-dlp option.
- Requests that return non-2xx statuses are errors (Go's page/thumbnail
  fetches accepted any response). Error messages omit URL query strings,
  which contain signatures and your IP.
- A connection that stops sending data for 30 seconds is dropped. Go had no
  limit once a response had started.
- Fragment URLs are stored as a prefix/suffix around the sequence number
  instead of `Sprintf` templates with `%` escaped as `%%`.
- The 5-hour background URL refresh runs as one task per download instead of
  being started from each stream's writer loop.
- A temp directory named in a saved state file is only reused if it still
  exists.
- `--separate-audio` only makes the extra audio file when both audio and video
  were downloaded. Go also made a duplicate for audio-only downloads.

### Files and cleanup

- Only temp directories named `{video_id}__*` (the ones ytarchive creates) are
  ever deleted. Go deleted whatever directory a state file named, so a
  corrupted state file could point it at any directory.
- The `publish_date` template value is always `YYYYMMDD`. Go kept the raw
  value, which for newer pages includes a time and offset.

### Output and signals

- The progress line is written to stderr (Go used stdout), so stdout stays
  clean for `--info-only` output.
- After the first Ctrl-C (which stops the download and leads to the
  merge/save questions), a second one exits immediately, matching the effect
  of Go's `signal.Reset`.

## Platform support

Linux and Windows are the primary targets, macOS is secondary. Go built for
more targets but only supported Linux and Windows builds.

- **TLS uses rustls** (with the `ring` crypto library) on every platform
  instead of Go's built-in TLS. Certificates come from the operating system's
  store. No OpenSSL is needed, so the Linux release builds are static and run
  on any distribution.
- **Windows console handling** (port of `util_windows.go`): the system is kept
  awake while ytarchive runs and the console's QuickEdit mode is turned off;
  both are restored on exit. Go turned QuickEdit off without the
  `ENABLE_EXTENDED_FLAGS` bit, which Windows requires for the change to take
  effect, so in Go it had no effect. ANSI colors are enabled explicitly
  (Go used go-colorable).
- **Portable file names on every OS**: control characters are replaced, and
  names Windows reserves (`CON`, `NUL`, `COM1`, …, also with an extension) or
  that end in a dot or space are adjusted. Go only replaced `<>:"/\|?*`.
- **The `.ffmpeg.txt` command uses the platform's quoting**: POSIX shell
  quoting on Linux/macOS, Windows command-line quoting on Windows. Go always
  used POSIX quoting.
- **`ffmpeg`/`yt-dlp` next to the executable are found**, in addition to
  `PATH` (handy on Windows). Go also allowed binaries in the current
  directory.

## Go bugs fixed during the port

1. **Filename blacklist was never applied.** `FormatFilename` blanked
   `description` and then immediately overwrote it with the real value, so
   `%(description)s` in a template inserted the whole description.
2. **Template expansion could loop forever.** `FormatPythonMapString`
   re-scanned substituted values, so a title containing its own placeholder
   (e.g. `%(title)s`) never finished. Substitution is now single-pass.
3. **Long-name truncation was too small for repeated titles.** When a
   template used `%(title)s` more than once, only one copy's worth was
   removed. Every copy is now shortened enough to fit.
4. **Session cookies were discarded.** Cookies with expiry `0` were given a
   1970 expiry date, which made Go's cookie jar drop them.
5. **`--live-from` 7-day check compared different units.** It compared a
   fragment count against a number of seconds.
6. **Missing start timestamps crashed.** Slicing an empty timestamp string
   panicked; malformed googlevideo `id` parameters did too.
7. **"Try N more times" never retried.** `ContinueFragmentDownload` promised
   extra attempts for fragments behind the head but didn't reset the try
   counter, so the download loop exited immediately and the fragment was
   dropped.
8. **One bad fragment ended the whole download.** On an ended stream, a
   fragment that failed permanently marked the stream finished, silently
   dropping everything after it (now skipped and reported, see above).
9. **Slower workers gave up early.** When one worker reached the last
   sequence it marked the stream finished, and other workers abandoned the
   fragments they were still retrying. Running out of sequence numbers now
   only stops that worker.
10. **Resuming with a missing data file produced a broken file.** Go marked
    the download as resumed and continued writing into a new empty file. It
    now starts over.
11. **MP4 box scanning could hang and was incomplete.** A zero-length box made
    `GetAtoms` loop forever, and only the first 8 KiB of each fragment was
    scanned for `sidx`/`ftyp`.
12. **The ffmpeg command could reference a missing thumbnail.** The arguments
    were built before the thumbnail download, so a failed download broke the
    merge. They are now built afterwards.
13. **The audio/video mismatch warning never fired.** The fragment counts it
    compared were never incremented.
14. **Page downloads failed with HTTP/2 errors** (port-specific, found while
    testing). With a Firefox user agent YouTube sends ~20 KB of response
    headers, above the HTTP library's 16 KB default. The limit is raised.

## Not ported

These parts of the Go source were unreachable or unused there, so they were
left out:

- **InnerTube player request** (`DownloadWebAPIPlayerResponse`), the `ytcfg`
  scraping that fed it, and **SAPISIDHASH** authentication. None of them are
  called in dreammu.
- **DASH manifest parsing** (`GetUrlsFromManifest`, `MPD` types): never
  called in dreammu, since yt-dlp provides the URLs.
- **UMP parsing** (`yt_ump.go`): never called.
- **Slow-fragment URL refresh**: Go counted slow fragments, but the refresh
  call is commented out.

Not ported although it worked in Go:

- **Version banner**: Go printed its version at startup; use `--version`.
